# Backup Security Strategy
# Project Overview
This project focuses on designing a basic backup strategy for a small organisation to protect important data and ensure recovery in case of data loss.

# Objective
To understand backup security, data protection, and recovery methods.

# The 3-2-1 Backup Rule
3 Copies: Keep three copies of important data, including the original.
2 Storage Types: Store data on two different types of storage.
1 Offsite Copy: Keep one copy in a separate, secure location.
# Backup Schedule
Daily Backup: Back up important files every day.
Weekly Backup: Perform a full backup every week.
Monthly Testing: Test backups and review security every month.
# Security Measures
Encryption: Encrypt backup files to protect sensitive information.
Strong Passwords: Use strong passwords and multi-factor authentication.
Access Control: Allow only authorised users to access backups.
Ransomware Protection: Protect backups from unauthorised changes and deletion.
# Recovery Plan
Identify: Identify the cause of data loss.
Select: Choose a clean and recent backup.
Restore: Restore the required files.
Verify: Check that the restored data is complete and usable.
Document: Record the recovery process and results.
# Why Test Backups?
Backup testing confirms that files can be restored correctly when needed. It helps identify corrupted backups and recovery problems before an emergency occurs.

# Tools Used
Google Docs: To prepare the backup strategy document.
GitHub: To store and submit the project files.
# Project Outcome
A basic backup and recovery strategy was designed using the 3-2-1 backup principle. This approach helps reduce the risk of permanent data loss and improves organisational data security.

# Conclusion
Following the 3-2-1 backup rule, applying security measures, and testing backups regularly can help a small organisation protect its data and recover from unexpected incidents.
